General Idea:

- UI applications (whether that might be a Qt desktop GUI, or a physical Stelltisch replica) should not depend directly on the classes within `Openstw::SpDr`, such as `Tile` and `FeatureLayer`
- Those applications should only ever interact with a public facade class offered by `Openstw::SpDr`, which provides information in the form of description objects, such as `TileDescription` and `FeatureLayerDescription`, and signals and slots for emitted aperture state changes and receiving button input
- This allows us to easily implement networked play at a later date, since the information exposed by the facade class are very easy to serialize and transfer over the network. No object graphs need to be replicated, only simple lists of aperture and button identifiers and their state (which is comprised of just a few enumeration values)
- The new design would also make it much easier to implement the `Openstw::CanLink` component, since it would no longer need to construct little shim objects for each tile and feature layer object within `Openstw::SpDr` in order to catch aperture state change notifications and send button input, but could rather just directly interact with the events generated by the facade class using its hardware mapping tables
- On the `Openstw::Gui` side, we would need to implement a helper `Aperture` class (different from the one in `Openstw::SpDr`) which holds the current `Openstw::SpDr::ApertureState` (which we receive from the facade class). This makes it easy for renderer code to hang on to the aperture objects it needs. Every time we receive a signal that tells us that an apertures state has changed, we find our local aperture object, update its state, and force the tile it belongs to into updating and redrawing itself
- The `Openstw::Gui` application can simply take the `TileDescription` and `FeatureLayerDescription` objects provided by the `Openstw::SpDr` facade class and build those local `Aperture` objects, as well as local feature layer graphics objects (which then no longer need a reference to the `FeatureLayer` subclass objects within `Openstw::SpDr`, just a reference to a `FeatureLayerDescription` object)
